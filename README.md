# jntsuppliers.com: static site

The site is plain HTML and CSS built with [Astro](https://astro.build), plus one PHP file (`public/quote.php`) for the quote form.
It has no database, no CMS and no JavaScript framework. The built site is under 1 MB.

## Commands

Node runs in Docker (`node:24-alpine`), because Astro 7 needs Node 22.23 or newer.

```bash
dev/npm.sh install            # first time only
dev/npm.sh run dev            # live-reload preview at http://localhost:4321 (the form won't send here)
dev/npm.sh run build          # build to dist/

cd dev && docker compose up -d --build
# http://localhost:8091  built site on Apache + PHP 8.3, with .htaccess, the same setup as the host
# http://localhost:8027  Mailpit: form emails land here, nothing is really sent
```

Staging build for review at `https://www.jntsuppliers.com/new/` (adds noindex, no sitemap, no root redirects):

```bash
SITE_BASE=/new/ STAGING=1 PUBLIC_TURNSTILE_SITE_KEY=<real site key> dev/npm.sh run build
```

## Where things are

| What | Where |
|---|---|
| Phone, email, address, hours, claims | `src/data/site.ts` |
| Product text, grades, specs, directions | `src/content/products/*.md` |
| Design tokens and all CSS | `src/styles/global.css` |
| Pages | `src/pages/` |
| `.htaccess` (security headers, redirects) and `robots.txt` | generated by `scripts/postbuild.mjs` |
| Quote form handler | `public/quote.php`, configured by `form-config.example.php` |
| Scene images (AI-generated, general scenes) | `src/assets/scenes/01–04.jpeg`; prompts in `IMAGE-PROMPTS.md` |

To add a product, copy a file in `src/content/products/`, change it and rebuild. Lists, menus, the footer and the sitemap update automatically.

## Quote form

Spam and abuse checks, in order:
1. POST only, with a same-origin check.
2. A hidden honeypot field and a minimum fill time of 3 seconds. Bots that trip either one get a fake success.
3. Rate limit: 5 submissions per IP per hour.
4. Server-side validation, with line breaks stripped from every value used in a header.
5. Cloudflare Turnstile, shown on the form as a "Spam check" and verified on the server. Without a real key, builds use Cloudflare's test key, which always shows the "Verify you are human" checkbox and the "For testing only" note.
   - To set up: in the Cloudflare dashboard, go to Turnstile and add a widget for `jntsuppliers.com` and `www.jntsuppliers.com` with **Widget mode: Managed**. Cloudflare has no setting that makes every visitor click. In Managed mode most visitors see the widget tick itself, and suspicious visitors must tick the box.
   - Build with `PUBLIC_TURNSTILE_SITE_KEY=<site key>`, and put the secret key in the config file.

The email is sent with PHP `mail()` from `website@jntsuppliers.com`, with Reply-To set to the customer's address.

Settings and the Turnstile secret go in `/home/jntsuppl/jnt-form-config.php`, outside `public_html`.

## Before go-live: confirm with the client

- [ ] **15+ years** in business, and island-wide delivery. These come from the old site. Change `claims` in `src/data/site.ts` if either isn't true.
- [ ] Street address and opening hours (`address`, `hours` in `site.ts`), and the exact Google Maps place link.
- [ ] Pack sizes. The site says "5 L can · bulk on request" because the product photos show 5 L cans; IPA is shown in drums.
- [ ] Which products have safety data sheets. The site says "SDS on request" for all of them, and SDS, specification and COA for IPA.
- [ ] Is "OMINI Press Essentials" (on the can labels) their own brand or a supplier's? If it's a supplier's, they need permission to show those photos.
- [ ] An original vector logo. `src/components/Logo.astro` is a redraw.
- [ ] The founder quote is his own wording from the old About page. Check he's happy with it.
- [ ] Real Facebook page link (`site.ts`).

## Guides (`src/content/guides/`)

The four guides were drafted from the product data plus standard pressroom practice. Set `updated:` in a guide's front matter when it changes.

## Go-live steps (on the server)

1. Make room: check `public_html/wp-content/cache.tar.gz` (109 MB) and delete it. A copy is kept locally in `../public_html`.
2. Build for staging (see above) and upload `dist/` to `public_html/new/`. Put the config file in `/home/jntsuppl/`, with `thanks_url` set to `/new/contact/thanks/`.
3. After the client approves: remove WordPress from `public_html` (the full backup is in `../public_html` and `../jntsuppl_wp821.sql`), do a normal build, upload `dist/` to `public_html/`, and drop the WordPress database in cPanel.
4. In cPanel: create `website@jntsuppliers.com` (or allow it as a sender), turn on SPF and DKIM under Email Deliverability, and add the Turnstile keys. Then send a test enquiry.
5. If cPanel's MultiPHP Manager adds a PHP handler block to `.htaccess`, keep that block.
6. Search engines:
   - Verify the domain in Google Search Console and Bing Webmaster Tools with a DNS TXT record, so no verification files go on the server.
   - Submit `https://www.jntsuppliers.com/sitemap-index.xml` to both.
   - Use URL Inspection to request indexing of the home page and the 5 product pages.
   - Over the following weeks, check the Pages report: old WordPress URLs should show as redirected (301) or removed (410), not as 404 errors.
   - Create or claim the Google Business Profile. It needs the street address; add the same address to `site.address` in `src/data/site.ts` so the structured data matches.
7. Delete the `localcopy` FTP account and remove its password from `../.env`.
